## 一、三条总纲

1. **改一处只读一个文件。** 定位成本高于实现成本时，先拆结构再改功能。
2. **可回滚。** 每批独立提交；**"纯搬移"与"行为变更"绝不混在同一个提交**（否则出问题无法二分定责）。
3. **可验证。** 能机器判定的规则必须机器判定；只能人判的，写进本文并给判据。

## 二、改动流程（六步，缺一步不算完成）

| # | 步骤 | 判据 |
|---|---|---|
| 1 | **查文档**：`docs/architecture.md` 找域，`MEMORY.md` 搜"是否被故意去掉过" | 能说出这次改动落在哪个层/哪个文件 |
| 2 | **定影响面**：双端三问（§4.6）、打桩面（§4.1）、数据兼容（§4.3） | 能列出会被波及的测试与端 |
| 3 | **先测试**（行为变更）：失败测试 → 改代码 → 变绿 | 新增/修改的用例能单独跑 |
| 4 | **改**：单一意图；顺手发现的别的问题**另开一批** | diff 里没有无关改动 |
| 5 | **全量验证**：`pytest tests/ -q`（当前 **374 项**）+ `python scripts/quality_gate.py` | 全绿，且预算检查通过 |
| 6 | **提交 + 记录**：`CHANGELOG.md` 追加条目；按 §3.5 升版本号 | 提交信息写清"改了什么/为什么/怎么验的" |

**提交纪律**

1. 测试通过后**立即提交**，不长期挂工作区（历史教训：09-21~09-23 一整批改动滞留，靠别人发现才补提交）。
2. 提交前 `git status` 核对，**运行时产物与用户状态一律不带**：`config.json`、`pending_*.txt`、`_logs/`、`_state/`、`_cache/`、`_inbox/`、`app_releases/*.apk`、`android/toolchain/`、`android/app/build/`、`.pytest_cache/`。
3. **只纠正本窗口自己写错的**署名/条目；别人窗口的历史错误指出即可，不代改。
4. **纯搬移提交禁止夹带行为改动**：不改逻辑、不改注释、不重命名。搬完行为不变是它唯一的验收标准。
5. 一次提交只服务一个目的。重构与修 bug 混提 = 回滚时连坐。

### 「一个提交 = 一个意图」，不是「一个文件」

这条纪律常被误读成"一次只能改一个文件"，**不是**。约束的是**提交粒度**，不是文件数量：

| 场景 | 提交方式 |
|---|---|
| 一个需求涉及后端 + 前端 + 测试 + 文档（如"搜索加高亮"） | **一个提交**——它们共同构成一个意图 |
| 一次对话里提了多个互不相关的要求（"加高亮" + "修上传超时" + "改文案"） | **多个提交**——不需要你分开提，我按意图拆、逐个跑测试、逐个提交 |
| 一个需求里顺手发现另一个 bug | 先按原意图提交，再单独修 bug 提交（提交信息里可互相引用 SHA） |
| 纯搬移 + 顺手改了一行逻辑 | **拆**：搬移一个提交（行为不变），逻辑改动另一个 |

**拆不拆的三个判据**（任一成立就拆）：
1. **能否独立回滚**——只想回滚其中一件事、不想动另一件 → 拆；
2. **性质是否相同**——纯搬移 vs 行为变更、重构 vs 修 bug、功能 vs 文档订正 → 拆；
3. **提交信息是否需要写"顺便"**——需要写，就已经是两个意图了 → 拆。

反例（真实教训）：把"面板加排序"和"修上传超时"放一个提交，线上出问题时无法二分定位，
回滚还会把好的改动一起撤掉。

**结论**：一次提多个要求完全没问题；要守的是"每件事有自己的提交、自己的测试结论"。

## 三、量化预算（机器强制）

### 3.1 上限

| 维度 | 上限 | 适用范围 | 判定代码 |
|---|---:|---|---|
| **物理行**（含空行与注释） | **800** / **700** | `.py` / `.js` 为 800；`.kt`（`android/app/src/**`）为 **700** | F001 |
| **有效代码行** | **400** / **500** | `.py` / `.js` 为 400；`.kt` 为 **500**（Compose 声明天然啰嗦，无 AST 按"非空非注释行"近似） | F005 |
| 单函数行数 | **50** | 所有 `.py` / `.kt`（Kotlin 为近似值，见下） | F002/F003 |
| 单函数圈复杂度 | **15** | 所有 `.py` / `.kt`（Kotlin 为近似值，见下） | F002/F003 |
| 静默吞异常 | **只降不升** | `except Exception: pass` / 裸 `except: pass` | F004 |
| 新增文件 | 两个维度都要满足 | 未登记且超对应语言上限（py/js 800·400，kt 700·500）即违规 | F001/F005 |

**适用范围覆盖所有代码文件**（2026-10-19 3.7.42 修正）：此前 `SKIP_DIRS` 把整个 `android/`
跳过了，等于 Kotlin 源码不受任何文件行约束（`MainActivity.kt` 2739 行也没人管）。
现在只跳过构建产物与工具链（`build/`、`toolchain/`、`.gradle/`），源码在闸门内；
`build.gradle.kts` 属构建脚本，不纳入。

Kotlin 侧的限制：
- **文件两维**（**700 / 500**，与 Python 的 800/400 不同：Kotlin 的 `@Composable` 参数与链式修饰符天然占行）已生效，代码行按"非空、非 `//`、非 `/* */`"近似（`_approx_code_lines`）。
- **函数两维**（50 行 / CC 15）**3.7.46 起接入、2026-10-20 由 80 行翻到 50**，由 `scripts/gate_kt.py` 提供
  （Kotlin 无 `ast`，用括号平衡扫描器近似：基线 1 + `if`/`while`/`for`/`catch`/`&&`/`||`/`?:`
  各 1 + `when` 每分支 1；嵌套 `fun` 是独立单元，不计入父函数）。
  **它是近似值，不是精算**——与 Python 侧 radon 对齐口径的精度不同，临界 case 以 review 为准。
  接入 detekt/ktlint 后可换成精确值，届时只需替换 `gate_kt.kt_functions` 这一处实现。
- 接入前 `.kt` 只量文件行、函数列表恒为空，等于 Kotlin 侧"函数多长多复杂"完全无人管
  （三次 Kotlin 重构都只能靠人肉看行数）。  接入后首次清点即暴露 7 个超标函数，
  其中 `MainActivity.App` 1327 行 / cc 162（已于 3.7.48 清偿，现为 15 行 / cc 1）。
- 存量 1 个超标文件已登记 `docs/quality-budget.json`（cap = 登记时真实值，**只降不升**），
  每条都写了拆分目标 `target`，`test_every_budget_debt_has_a_target` 会盯着不许"登记完当没事"。

**为什么是两个维度**（2026-10-19 由单一"600 行"改为现标准）：

- 只判物理行会把**排版问题**误判成**结构问题**：`app.py` 曾有 1008 物理行，其中 483 行空行、
  211 行注释，真实代码只有 **314 行**——它当时被当成"巨石"报债，实际该修的是空行。
- 只判代码行会放过真正臃肿的文件：`app.js` 2974 行代码、注释为零，物理行与代码行几乎相等。
- 因此：**物理 800 管"读起来累不累"，代码 400 管"逻辑有多重"**；两个都超才是真该拆。

**有效代码行的口径**：非空、非 `#` 注释、非 docstring 行。
docstring 计入会诱使"靠堆注释达标"或"拆注释减重"，两者都污染判断。
判定函数：`scripts/quality_gate.py::code_lines`。

### 3.2 度量工具与口径

**工具**：`scripts/quality_gate.py`（自研，仅标准库，零依赖）。

为什么不用现成工具当关卡：本项目需要的是"**数值 + 预算 + 棘轮 + 项目专属规则**"四合一。
`radon`/`ruff` 只给数值，不给预算；且项目要求断网可用、不为检查引入 pip 依赖。

**口径**（`quality_gate._cc`，与 **radon 6.0.1** 对齐，作为固定契约不得随意改）：

- 基线 1；`if` / `elif` / `for` / `while` / `except` / `assert` / 三元 / `match case` 各 +1；
- `for…else` / `while…else` 的 `else` 分支再 +1；
- 布尔链里**每个多余的 and/or** +1（`a or b or c` 记 +2）；
- 每个推导式 +1，另 +1/每个 `if` 子句；
- **不计 `with`**（radon 不计）；
- **不递归进嵌套函数/类**（嵌套函数是独立单元，父函数若把它算进来就是重复计数）。

**交叉校验记录**（2026-10-18，radon 6.0.1，10 个文件 448 个函数）：
**446 个完全一致**，2 个差 1（radon 对个别 `try` 分支的计数差异）。改口径前必须先跑一次同样的交叉校验，
并在 `CHANGELOG.md` 记录，否则棘轮额度全部失真。

**可选辅助**：

| 工具 | 定位 | 用法 |
|---|---|---|
| `radon` | 交叉校验/人工体检 | `pip install radon`（建议装进隔离环境）→ `radon cc -s -a app.py` |
| `ruff`（`ruff.toml`） | 编辑器内即时反馈 | 装 Ruff 插件；**不作为关卡**（无法表达预算与棘轮） |

### 3.3 棘轮机制（存量债务怎么处理）

存量已超标的文件/函数登记在 **`docs/quality-budget.json`**，`cap` = 登记时的真实值：

- **只降不升**：改完只要不超过冻结额度就通过；一旦降下来，跑 `--update` 固化新值，**再也回不去**。
- **新增超标**：直接失败，要求拆分或显式登记债务（`--init` 会把新文件带进来，等于认领）。
- **债务必须写目标**：`files[x].target` + `files[x].why`，否则复审时无法排期
  （`tests/test_engineering_rules.py` 会强制检查这一点）。

当前债务快照（2026-10-20 · 3.7.50）：**0 个文件**超限、
**10 个函数债务**（全部为测试函数 cc 16~21，刻意保留；**生产函数债务已清零**）、
静默异常 **30 处**。

| 维度 | 现状 |
|---|---|
| 文件（物理 800 / 代码 400）· Python/JS | 全部达标；最长的业务文件是 `services/scan.py` 586 / 392 |
| 文件 · Kotlin（700 / 500） | 全部达标；45 个文件中最长的是 `AppState.kt` 530 / 484。`MainActivity.kt` 2739 → 1584 → **364**（3.7.50 按域拆成 Shared/State/Nav/Sheets/Bars 五块），销账 |
| 生产函数（50 行 / cc 15） | Python 与 Kotlin 全部达标：最长函数 50 行、最高 cc 15（`InboxItemRow` / `downloadOnce`）。`MainActivity.App` 千行巨石已于 3.7.48 拆为 `App`(15 行) + `AppState` + 20+ 子 composable |
| 测试函数 | 10 项：断言密集的多段式用例，**刻意保留**（理由见 `docs/architecture.md` §8.2） |
| 静默吞异常 | 30 处：判据见 §4.4 |

历史（3.6.83 及以前）：7 个文件超限、18 个函数、41 处静默异常。拆解过程见
`docs/architecture.md` §八 与 CHANGELOG 的 3.6.77 ~ 3.6.84 各条。

### 3.4 超标了怎么办（三种合法路径，按优先级）

1. **拆**（默认）：函数拆具名步骤；文件按域拆模块。拆分必须"纯搬移"提交 + 全量测试。
2. **认领债务**：确实暂时拆不动 → `--init` 登记，并在 `why` 写清为什么现在不拆。**登记不等于豁免**，它只是把上限冻在当前值。
3. **显式提额**：只给"客观上必须变长"的情况（如生成的常量表）：
   `python scripts/quality_gate.py --raise app.py 900 --why "新增 xxx，下批拆走"`
   或 `--raise-code app.py 450 --why "..."`（提有效代码行额度）。
   **`--why` 必须写明"哪一批/哪个版本拆走"**；没有到期日的提额等于永久豁免。

**搬迁/还债后必须跑 `--prune`**：重建债务表（删已修复与已搬走的键、按当前实测重算）。
不跑的话，函数换了文件会被当成"新增超预算"而假红（Stage 6 首次搬迁即遇到）。

**禁止**：为了让测试变绿去删断言、放宽 `limits`、或把新代码塞进已冻结的文件再调 `--update`
（`--update` 只写 `max(当前, 旧值)`，抬不上去）。

### 3.5 版本号（三轴，各自走）

| 轴 | 落在哪 | 何时升 |
|---|---|---|
| **面板** `PANEL_VERSION` | `VERSION` + `app.py` + `static/index.html` 的 `?v=`（三处必须同步，`test_static_boot` 会拦） | 改面板/网页即升：修 bug → patch，新功能 → minor，不兼容 → major |
| **APP** | `android/app/build.gradle.kts` 的 `versionName`/`versionCode` | 每次 APP 改动当场升并派发；`versionCode` **全局单调递增** |
| **接口** `SERVER_API_LEVEL`/`MIN_APP_API` | `app.py` ↔ APP `Api.kt` 的 `APP_API_LEVEL` | **仅破坏性接口改动** +1（新增字段不算） |

APK 派发：文件名 `Index-v<versionName>-<versionCode>.apk`，`app_releases/` **同刻只留 1 个包**。

**出包命令（只用 debug 变体，全程离线）**：

```
toolchain/gradle-8.11.1/bin/gradle :app:assembleDebug --offline -Pvc=<比上一包更大的整数>
scripts\dispatch_apk.bat <新 APK 的 Windows 绝对路径>
```

- **不要用 `assembleRelease`**：本项目没有 `signingConfigs`，release 产物是**未签名包**（装了起不来）；
  而且 release 变体会多跑 `lintVitalAnalyzeRelease`，它要的 `groovy` / `play-sdk-proto` 不在本机缓存，
  于是报 `Could not download …` —— 这不是"没网"，是**用错了构建变体**（2026-10-26 踩过，详见 CHANGELOG）。
- **`-Pvc` 必须手工递增**：自动值是构建时刻的 `yyMMddHH`，同一小时出第二个包会重复，
  手机按整数比较会判定"无更新"。
- 报构建失败前先看**是哪个 task 失败**，再判断是不是环境问题。

## 四、结构纪律（每条都有事故来源）

### 4.1 打桩面就是架构

测试用 `monkeypatch.setattr(app, "INDEX_FILE", ...)` 这类方式隔离副作用，**打桩点就是事实上的接口**。
代码搬家时打桩点会跟着漂：搬到新模块后，打在 `app` 上的桩**不再生效**，测试表面变绿、实际写穿真实库。

- **搬迁前先 grep**：`grep -rn 'setattr(app' tests/`，列出涉及的打桩点。
- **跨模块导入最危险**：`test_crawl_parallel` 打的是 `app.subprocess.Popen`。新模块若自己 `import subprocess`，桩失效 → **测试会真的拉起爬虫子进程**。
- **规矩**：搬一个域，必须同时（a）在测试里补新模块的打桩，(b)在提交信息里写明"打桩面从 A 迁到 B"。
- **终极解法**：状态对象化，把打桩面收敛成"对象的属性"一处。这也是 `app.py` 拆分的前置条件。

### 4.2 单一事实源

- **同一个常量只许有一处定义。** 历史问题：`_CRAWL_LOG_FILE` 在 `app` 与 `services.crawl` 各有一份，测试要两边都打桩。
- `from X import Y` 是**值绑定**：`X.Y` 变了，导入方看不到。可重绑定的量必须 `import X` 后用 `X.Y` 访问。
- 新模块复用常量必须**通过模块访问**（`from services import crawl as sc; sc._CRAWL_LOG_FILE`），不得二次赋值。

### 4.3 状态唯一持有者

- 进程内只允许**一处**持有可变状态；`app.py` 的 `_INDEX`/`ORIGINALS`/`NORM_TO_CANON`/`REGION_COVERS` 是历史遗留的"散装状态"，新增状态**不得**再往这里加。
- 两边都 `global` 赋值 = 分叉成两份状态，症状是"改了没生效/重启后打回原形"。
- 后台写盘线程**必须锚定路径快照**（2026-10-13 曾写穿真实文库）：新线程拿到的路径要在创建时固化并校验上下文，不能中途读取被替换的全局。

### 4.4 异常可见性

- **业务失败禁止静默**：`except Exception: pass` 一律改为 `log.exception("…（用户可见后果）")`。
- **资源清理类**可以静默，但必须**显式写出窄异常 + 说明**：
  ```python
  except OSError:      # 清理临时文件失败无副作用，不记为业务失败
      pass
  ```
- 批量操作前的 `meta.snapshot()` 失败**必须发声**——那是用户唯一的"撤销点"。
- **允许保留的四类**（当前 30 处，全部属于其中一类；新增必须对号入座）：
  1. **日志设施自身的故障**（`wnacg_base.log` / `launcher_core.log_error` 写盘失败）——
     再抛异常会把主流程带崩，且无处可记；
  2. **进程退出前的清理**（`server_close`、关闭压缩包/上传句柄、`rollback`）——
     已经走到最后一步，失败也没有补救路径；
  3. **尽力而为的外部命令**（`taskkill`、`terminate`、`wmic` 枚举）——
     失败由返回值反映，调用方会显示"未在运行"；
  4. **终端能力适配**（`stdout.reconfigure`、`iconbitmap`、DWM 暗色标题栏）——
     换个终端/系统版本就该优雅降级，不是业务失败。
- **不属于以上四类的，一律改为记录**：`except Exception: pass` → `log.exception("…（用户可见后果）")`。
  3.6.84 按此判据清掉 11 处（保存配置、远程令牌落盘、爬虫断点损坏、语言分类失败、
  残留进程清扫、UI 队列调度、快照保留策略等），41 → 30。

### 4.5 迁移/一次性脚本

- 执行流程与 `argparse` **必须在 `main()` 内**，文件末尾 `if __name__ == "__main__": main()`。
  模块级直接执行会被 `import` 触发（`retry_all_failed.py` 曾因此让 `--help` 直接开爬）。
- 辅助脚本必须支持 `--help` 且**不产生副作用**。

### 4.6 双端对齐（面板 / APP）

开工前三问：① 只动了一端吗？② 另一端有同质能力/同质视图吗？③ 不同步的理由成立吗（仅"离线模式/本地下载"这类单端能力可豁免）？

- 改排序/筛选语义后**必须逐端实测**（网页 `renderFeedPartition`、APP `HomeScreen`、封面缓存）。
- 新增 HTTP 端点或爬虫任务要**先列"四处"再写代码**：`services/crawl.py`、`app.py` 端点群、
  `static/app.js`、APP `Features.kt`（对应 CrawlScreen / 视图）。

### 4.6b 语言包（术语先对齐，别写错）

**这里是「1 基准 + 7 译文」= 8 种语言，不是"双语"。** 简体中文原文就是 key 本身（基准语言），
译文包是 `zh-Hant / en / ja / ko / ru / th / vi` 七套；说"双语化""中英双语"都是错的
（2026-10-26 我在交付说明与 CHANGELOG 里写成"双语化"，被用户当场纠正）。

- 网页：`static/js/i18n_lang_<code>.js`（`zh-Hant` 用大写 H），t()/tf() + `data-i18n`。
- APP：`Strings*.kt` → `AppI18n.s()/sf()`；**新批次一个文件装 7 语**（`I18N_EXTRA<n>`），
  老的四件套是历史"一个文件两语"布局，**不要再往里追加**。
- 术语：key 含中文；`%1..%9` 占位集合必须与中文 key 一致（语序可换）；emoji 不进 key；
  **磁盘文件名 / 格式记号不译**（源码标 `// i18n:data`，缺口报表豁免）。
- 数完再说：报"某页已七语化"之前跑一次 `python scripts/i18n_gap_report.py --quiet`，
  别凭印象。

### 4.7 爬虫域

- 脚本只放 `crawlers/`；导入一律 `from crawlers import x`，**禁止裸 `import crawl_xxx`**（第二份模块实例 → 打桩失效 → 写穿真实日志）。
- `APP_DIR` 语义恒为 `_app`（config/清单/`_inbox`/`_logs`/`_state` 的基准），不得改成脚本目录。
- 用户运行时数据（`pending_*.txt`）留在 `_app` 根，不随代码走；程序目录内**绝不建中文目录**（`_` 前缀 = 功能目录）。

### 4.8 测试纪律

- 造文件/时间戳**一律用显式固定值**，绝不用"现在"（DOS 时间 2 秒粒度、ntfs 15.6ms tick 都踩过）。
- 测试必须隔离 `common.CONFIG_FILE`、`meta_store.DB_PATH`、爬虫的 `LOG_FILE/STATE_FILE/STAGING_DIR/_log_fp`；**绝不动 `APP_DIR`**（面板自重启 mtime 判据）。
- 不许写"永远为真"的空测试；删断言必须给出替代覆盖。
- **对文库根（`D:\<文库根>`）的任何添加，验证后必须清除**：为验证而建的社团文件夹/作品、探测脚本、
  pytest `--basetemp` 残留一律不留。优先用 `tmp_path`；确需写真实文库的，验证完立刻删干净。

### 4.8b 实测纪律（亲眼验收只准跑测试模式）

**事故来源**：2026-10-26 前后共三次，agent 直接在完整模式面板上截图实测，真实封面/内页
一进多模态上下文即触发内容审查（content-filter），**会话当场截断、工作进度作废**
（最近一次：实测续读页时死掉，实测只做了三分之一）。而 3.6.118 早已为此建好测试模式，
纯属没有执行。

**铁律：前端改动必须过亲眼实测；实测只准跑测试模式（`--safe-images`，全端点占位图），
绝不对着完整模式面板截图。无条件实测的（非多模态模型 / 无内置浏览器）不测，明确标注
「未实测」，改用 pytest + quality_gate + 几何探针（getBoundingClientRect、computed
style）等替代手段；CHANGELOG 的验证段如实写，虚报「已实测」视同违反 §4.4 异常可见性。**

标准动作（agent 一条命令，占位图探针通过才算就绪）：

    python scripts/test_panel.py start    # 起 127.0.0.1:8767 测试实例，自检占位图
    # 内部浏览器开 http://127.0.0.1:8767/ 实测（回环免 token，封面/内页全是占位图）
    python scripts/test_panel.py stop     # 测完即停，不留常驻

- **探针是唯一机器判据**：`scripts/test_panel.py status` 中 `/cover` 任意参数逐字节等于
  `static/img/placeholder.png` 才算测试模式生效；不通过即完整模式，一律不得截图。
- `/api/panel/restart` 是原参数 exec 重启，**不会**把完整模式切成测试模式；运行中的
  8765/8766 面板一律默认按完整模式对待（SAFE_IMAGES 是内存标志，API 不暴露）。
- 用户自选的主题背景/横幅/图库图片不占位——实测这些页面时不截图，改用几何探针。
- 用户明确说「不要实测」时，视同本条的"无条件"分支：只跑机器验证，不碰浏览器。

### 4.9 高风险改造（事故重灾区专章）

`meta_store.sync_scan`（cc 67）、`app.scan_groups`（cc 46）、`app._import_process` 这类函数**没有任何单函数级测试**，
却是历史事故集中地。改造顺序固定：

1. **先补快照测试**：喂一组固定文件名 → 断言 `want_t` / 分组结果 / 落库行数；
2. 再按"输入→输出"边界拆函数；
3. 每拆一步跑全量测试 + 一次真实库的 dry-run（`migrate.py --dry-run` 或面板 `--import-only` 实例）。

**没有快照测试，不许动这些函数的结构。**

### 4.10 空白也是代码（排版纪律）

**事故来源**：Stage 6/7 搬迁按行号切片删除函数，函数前后各 2~3 行分隔空行被留下并相互叠加，
`app.py` 一度出现 31 处 ≥4 行空段、最长连续 46 行，**1008 行里有 483 行（48%）是空的**。
后果不是"难看"，而是判断失真——文件行数是"该不该拆"的主要依据，被空行撑虚后，
既可能把已经够小的文件误判成巨石，也会让不同时期的数字无法比较。

规则：

1. **连续空行 ≤2**：函数之间 2 行，类内方法之间 1 行，函数体内不留纯装饰性空行；
2. **交付前清空行**：一次搬迁/删除结束后必须回看被删区间两侧，把叠加的分隔空行收掉；
3. **不许用空行凑可读性**：需要分隔就写注释或小标题，而不是空 5 行；
4. **判断文件大小看"代码行"**（非空非注释），不只看总行数：
   `python scripts/quality_gate.py --stats` 输出两者的对照；
5. 闸门 `F104` 会拦下 >2 行空段（**跨行字符串内的空行不算**，那是内容不是排版）。

### 4.11 注释也是代码（F007）

**事故来源**：重构把文件拆了/改名了/删了，注释还写着旧名字。IDE 不报错、import 不报错，
只有读者会照着注释去找一个已经不存在的文件（"见 `static/app.js` 里的 renderCrawl"——
那文件早已拆成 13 片）。2026-10-20 的注释审计一次扫出 **29 处**，其中 8 处属于这一类；
另有 7 处把已经过时的标准（80 行 / 600 行 / 800·400 统一口径）写成了现状。

规则：

1. **改动涉及"搬 / 拆 / 改名 / 改标准"时，同一个提交里扫一遍受影响的注释**；
   历史事实可以留，但必须带时间限定词（"当时 / 曾 / 原本 / 拆分时"），否则读者会当成现状；
2. 注释里的路径、文件名、函数名必须能在当前代码里找到——找不到就改，或明确标注"已删除"；
3. 写完注释后自问一句："按这条注释去找，能找到东西吗？"。

闸门 **F007**（`scripts/gate_comments.py`）：注释与 docstring 里被反引号包裹的文件名
必须真实存在（三级解析：相对当前文件目录 → 相对项目根 → 全项目同名文件）。口径刻意保守：

- 只认**反引号包裹**的名字。写历史用普通文字（"原来的 static/app.js"），规则天然不误伤；
- 只扫注释（Python 的 `#` 与 docstring、JS/Kotlin 的整行 `//` `/*` `*`）；代码里的字符串不扫；
- 运行时产物（`_state/`、`config.json`、`meta.db` 等）本就不在仓库里，不参与判定；
- 确实要提"已经删掉的文件"，在该行写 `noqa: F007`（与 `# noqa: E402` 同惯例）。

## 五、文件放置（域即目录）

| 目录 | 放什么 | 不许放 |
|---|---|---|
| 根目录 | 入口（`app.py`/`index_launcher.py`）、跨域纯模块（`djc_parse.py`/`common.py`）、用户配置与运行时数据 | 新的业务实现、爬虫脚本、一次性脚本 |
| `panel/` | 面板服务端的低耦合子模块（无 app 依赖、优先纯函数） | 路由、依赖 `app` 全局的逻辑 |
| `services/` | 有状态的服务层（爬虫任务、未来的 library/archive 服务） | HTTP 装饰器 |
| `routes/` | **（规划中）** Flask Blueprint，按域一份，依赖 `app` 的 `create_app()` | 业务规则本体 |
| `crawlers/` | 爬虫五任务 + 维护脚本 | 被 `app.py` 直接 import 的库代码 |
| `scripts/` | 维护/检查脚本（`quality_gate.py`、事故恢复） | 常驻服务 |
| `docs/` | 规则、结构图、审计报告 | 运行日志 |

**新文件先问归属**：属于哪个域？答不上来，往往说明它不该独立存在，或该拆的域还没拆。

**文档与代码同提交**：改结构就同步 `docs/architecture.md` 的表；改规则就同步本文与预算表。
文档滞后比没有文档更糟——它会让人按错的图施工。

## 七、豁免流程

任何例外都必须**留痕**，只有三种形式：

1. **函数/文件**：登记进 `docs/quality-budget.json`（`--init`），并写 `target` 与 `why`。
2. **提额**：`python scripts/quality_gate.py --raise <file> <cap> --why "<理由与到期批次>"`。
3. **规则例外**（确实不适用）：在本文追加"例外条目"（规则号 + 文件 + 理由 + 失效条件），
   代码处加同号注释（如 `# 纪律例外 F102：<原因>`），否则视为违规。

**没有第四种**：不允许"这次先这样"。
